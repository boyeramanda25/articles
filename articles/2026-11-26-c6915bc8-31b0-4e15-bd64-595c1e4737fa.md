# 退款推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:c6915bc8-31b0-4e15-bd64-595c1e4737fa -->

## 问题场景

退款状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/refund/stream', (msg) => {
  state.count += 1;
  document.querySelector('#refund-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

在压测阶段，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使整体改动风险可控。

在实际落地时，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。

在迁移过程中，可以通过日志补充上下文信息，同时把结论沉淀进团队文档。

从长期维护角度看，先把最小可复现的用例固定下来，让排查路径更短。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。
