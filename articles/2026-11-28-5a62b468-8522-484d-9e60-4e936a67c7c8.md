# 归档组件的行为用轻量 DOM 测试固定下来

<!-- content-workspace-job:5a62b468-8522-484d-9e60-4e936a67c7c8 -->

## 问题场景

归档组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="archive">归档</p>');
console.assert(root.querySelector('.archive').textContent === '归档', 'render');
console.log('cases', 1, root.children.length, 10240);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

在实际落地时，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

在迁移过程中，可以通过日志补充上下文信息，保证每一步都可验证。

在跨团队协作时，要避免在高峰期执行这类操作，避免问题积累到难以收场。

上线初期，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。

在压测阶段，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

从排障效率看，要明确各项资源的释放时机，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使整体改动风险可控。

在跨团队协作时，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。
