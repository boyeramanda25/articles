# 审计展示组件用自定义元素封装

## 问题场景

审计卡片在三个页面各写一份，改样式要同步三处，很容易漏改。

## 实现步骤

继承 HTMLElement 并挂到 shadow root，样式天然隔离。

```javascript
class AuditCard extends HTMLElement {
  static get observedAttributes() { return ['title', 'value']; }
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }
}
```

声明 observedAttributes，属性变化时只更新对应节点。

```javascript
  render() {
    this.shadowRoot.innerHTML = `
      <style>.box{padding:10px;border:1px solid #ccc}</style>
      <div class="box"><b>${this.getAttribute('title') || ''}</b>
      <span>${this.getAttribute('value') || 0}</span></div>`;
  }
```

在 connectedCallback 里完成首次渲染，移除时解绑监听。

```javascript
customElements.define('audit-card', AuditCard);
const el = document.createElement('audit-card');
el.setAttribute('value', '38000');
document.body.appendChild(el);
```

## 注意事项

自定义元素名必须含连字符；shadow DOM 内的样式不会外泄，但外部也无法用普通选择器覆盖，需用 CSS 变量做定制入口。

在资源受限的环境下，建议在变更前留一份可回滚的快照，避免资源被长期占用。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

对于刚接手的同学，要明确各项资源的释放时机，确保线上行为始终可控。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，同时把结论沉淀进团队文档。

从排障效率看，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

对稳定性要求高的场景，优先用工具把现状量化出来再动手，让容量规划更有依据。

从排障效率看，要明确各项资源的释放时机，以便快速定位瓶颈。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

在资源受限的环境下，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。
