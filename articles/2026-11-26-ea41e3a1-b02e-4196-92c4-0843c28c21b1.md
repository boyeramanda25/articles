# 部门推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:ea41e3a1-b02e-4196-92c4-0843c28c21b1 -->

## 问题场景

部门状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/dept/stream', (msg) => {
  state.count += 1;
  document.querySelector('#dept-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

在迁移过程中，可以通过压测确认容量水位，之后再考虑扩大适用范围。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

对于刚接手的同学，要明确各项资源的释放时机，减少不必要的返工成本。

如果数据量继续增长，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

从排障效率看，要明确各项资源的释放时机，确保线上行为始终可控。

从可观测性角度，应确认依赖版本与运行环境一致，让容量规划更有依据。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。

在资源受限的环境下，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

针对这类偶发问题，尽量把决策依据写进变更说明，避免资源被长期占用。

从成本角度看，应当限定作用范围避免影响其他业务，保证每一步都可验证。

如果数据量继续增长，优先用工具把现状量化出来再动手，让容量规划更有依据。
