# 固定资产表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:991e57af-1f1c-409b-b1aa-2b4775c58fa8 -->

## 问题场景

固定资产录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  book: (v) => (/^\d+$/.test(v) ? '' : '固定资产必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

遇到复杂链路时，优先保证失败时能快速定位原因，减少不必要的返工成本。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使整体改动风险可控。

对于刚接手的同学，应定期回顾相关监控指标，让排查路径更短。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

在多人协作的项目里，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。

对于刚接手的同学，要明确各项资源的释放时机，减少不必要的返工成本。
