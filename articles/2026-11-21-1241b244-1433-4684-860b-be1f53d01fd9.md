# 用 SSE 向任务页面推送实时状态

<!-- content-workspace-job:1241b244-1433-4684-860b-be1f53d01fd9 -->

## 问题场景

任务的进度页面用轮询，每秒一次，几百个用户同时打开就把接口打满，大部分请求还没有新数据。

## 实现步骤

服务端保持长连接，响应头声明事件流类型并关闭缓存。

```typescript
res.writeHead(200, {
  "Content-Type": "text/event-stream",
  "Cache-Control": "no-cache",
  Connection: "keep-alive",
});
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
```

有新数据就往连接里写一条事件，格式是 data 加空行。

```typescript
const timer = setInterval(() => {
  res.write(`data: ${JSON.stringify({ t: Date.now() })}\n\n`);
}, 1000);
```

客户端断开时清理定时器，否则连接关了还在往里写，服务端句柄泄漏。

```typescript
req.on("close", () => {
  clearInterval(timer);
  res.end();
});
```

## 注意事项

SSE 只支持服务端到客户端单向通信，需要双向就用 WebSocket；中间代理可能缓冲响应，要显式关闭缓冲并调大超时。

如果数据量继续增长，优先用工具把现状量化出来再动手，让容量规划更有依据。

对于刚接手的同学，要明确各项资源的释放时机，以便快速定位瓶颈。
