# 给退款表加缓存时先挡住穿透请求

<!-- content-workspace-job:12443569-ce0f-4127-b828-e5765e2c156d -->

## 问题场景

退款表的详情接口被大量不存在的 id 请求，缓存里没有就去查库，查不到又不写缓存，同一个不存在的 id 每秒打几千次数据库。

## 实现步骤

正常结果写缓存并设置过期时间，键名带业务前缀便于清理。

```bash
redis-cli SET refunds:1 '{"id":1}' EX 60 NX
```

空结果也写一个短过期的占位值，挡住重复的穿透请求。

```bash
redis-cli SET refunds:999999 '__nil__' EX 30
redis-cli GET refunds:999999
```

观察命中率与数据库 QPS，穿透被挡住后 QPS 应大幅下降。

```bash
redis-cli INFO stats | grep -E 'keyspace_hits|keyspace_misses'
```

## 验证方法

对同一个不存在的 id 连续请求，数据库查询次数应只有第一次，后续直接返回空。

## 注意事项

空值缓存时间不能太长，否则数据补录后要等过期才可见；更彻底的做法是布隆过滤器或参数合法性校验，把明显非法的 id 直接拦掉。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

从排障效率看，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

对稳定性要求高的场景，优先用工具把现状量化出来再动手，让容量规划更有依据。
