# 归档展示组件用自定义元素封装

## 问题场景

归档卡片在三个页面各写一份，改样式要同步三处，很容易漏改。

## 实现步骤

继承 HTMLElement 并挂到 shadow root，样式天然隔离。

```javascript
class ArchiveCard extends HTMLElement {
  static get observedAttributes() { return ['title', 'value']; }
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }
}
```

声明 observedAttributes，属性变化时只更新对应节点。

```javascript
  render() {
    this.shadowRoot.innerHTML = `
      <style>.box{padding:10px;border:1px solid #ccc}</style>
      <div class="box"><b>${this.getAttribute('title') || ''}</b>
      <span>${this.getAttribute('value') || 0}</span></div>`;
  }
```

在 connectedCallback 里完成首次渲染，移除时解绑监听。

```javascript
customElements.define('archive-card', ArchiveCard);
const el = document.createElement('archive-card');
el.setAttribute('value', '10240');
document.body.appendChild(el);
```

## 注意事项

自定义元素名必须含连字符；shadow DOM 内的样式不会外泄，但外部也无法用普通选择器覆盖，需用 CSS 变量做定制入口。

在实际落地时，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

在迁移过程中，可以通过日志补充上下文信息，保证每一步都可验证。

在跨团队协作时，要避免在高峰期执行这类操作，避免问题积累到难以收场。

上线初期，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。

在压测阶段，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

从排障效率看，要明确各项资源的释放时机，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

结合团队现状，可以通过日志补充上下文信息，同时把结论沉淀进团队文档。

遇到复杂链路时，先把最小可复现的用例固定下来，让排查路径更短。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。
