# 商品表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:cd84377b-63c4-4a3b-b380-1814815dca9b -->

## 问题场景

商品录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  stock: (v) => (/^\d+$/.test(v) ? '' : '商品必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

在多人协作的项目里，应当拆分步骤以便中途校验，让新人上手时少走弯路。

从成本角度看，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从长期维护角度看，先把最小可复现的用例固定下来，降低同类问题再次发生的概率。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。

结合团队现状，可以通过压测确认容量水位，避免资源被长期占用。

从排障效率看，要明确各项资源的释放时机，确保线上行为始终可控。

上线初期，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。
