# 生产批次字典查询加上缓存后减少重复计算

<!-- content-workspace-job:335c3fd9-b98f-44c1-9399-5ebf82438a32 -->

## 问题场景

每次渲染生产批次详情都要重复计算同一组派生字段，调用量一上来 CPU 就被同一段逻辑吃掉。

## 实现步骤

把派生逻辑抽成只依赖入参的纯函数，加 lru_cache 并设定合理容量。

```python
from functools import lru_cache

@lru_cache(maxsize=1024)
def summary(ident, version):
    rows = fetch_rows(ident)
    return {"id": ident, "total": sum(r["qty"] for r in rows), "v": version}
```

数据变更时主动调用 cache_clear，或把版本号作为入参的一部分。

```python
def invalidate():
    summary.cache_clear()
    return summary.cache_info().currsize
```

监控缓存命中率，命中率长期偏低说明入参过于分散，缓存没有意义。

```python
a = summary("batch-1", 600)
b = summary("batch-1", 600)
print(a == b, summary.cache_info().hits)
```

## 验证方法

连续调用同一参数两次，第二次的耗时应显著低于第一次，且返回值完全一致。

## 注意事项

lru_cache 要求入参可哈希，传列表会直接报错；缓存会延长对象生命周期，大对象要设 maxsize。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

遇到复杂链路时，先把最小可复现的用例固定下来，防止出现隐性回归。

在跨团队协作时，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

在资源受限的环境下，要避免在高峰期执行这类操作，保证每一步都可验证。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

结合团队现状，可以通过日志补充上下文信息，保证每一步都可验证。
