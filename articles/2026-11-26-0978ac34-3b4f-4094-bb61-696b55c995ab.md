# 团队表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:0978ac34-3b4f-4094-bb61-696b55c995ab -->

## 问题场景

团队录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  size: (v) => (/^\d+$/.test(v) ? '' : '团队必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

在资源受限的环境下，建议在变更前留一份可回滚的快照，避免资源被长期占用。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在迁移过程中，可以通过压测确认容量水位，之后再考虑扩大适用范围。

在实际落地时，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使运维成本保持在合理区间。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

在迁移过程中，可以通过日志补充上下文信息，保证每一步都可验证。

从成本角度看，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。
