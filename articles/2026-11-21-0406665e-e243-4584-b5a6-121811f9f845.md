# 订单表的 JSONB 字段查询与 GIN 索引

## 问题场景

订单表把扩展属性塞进 JSONB 字段，查询时用 ->> 取值再比较，数据一多就全表扫，接口从几十毫秒涨到几秒。

## 实现步骤

包含关系用 @> 判断，语义清晰且能命中 GIN 索引。

```sql
SELECT id FROM orders WHERE payload @> '{"amount": 1}';
```

建 GIN 索引，注意操作符类要选对，默认支持包含与存在判断。

```sql
CREATE INDEX idx_amount ON orders USING GIN (payload);
```

只取个别键时用 ->> 输出文本，需要类型转换就在表达式里显式转。

```sql
SELECT id, payload->>'amount' AS v
FROM orders WHERE payload ? 'amount' LIMIT 5;
```

## 注意事项

GIN 索引写入比 B-tree 慢，更新频繁的字段要评估；jsonb_path_ops 体积更小但只支持 @>，需要键存在判断时要用默认操作符类。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

在实际落地时，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。
