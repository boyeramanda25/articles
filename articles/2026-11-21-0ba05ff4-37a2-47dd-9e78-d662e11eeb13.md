# 用 pre-commit 拦截gateway仓库的格式问题

<!-- content-workspace-job:0ba05ff4-37a2-47dd-9e78-d662e11eeb13 -->

## 问题场景

gateway仓库的提交里经常混进行尾空格、没换行结尾的文件，评审时为了这些细节来回打回，真正的问题反而没人看。

## 实现步骤

用 pre-commit 挂通用钩子，处理空格、行尾和文件结尾换行。

```yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
```

再挂语言相关的检查，与 CI 用同一个版本，避免本地过而线上挂。

```yaml
  - repo: https://github.com/golangci/golangci-lint
    rev: v1.59.0
    hooks:
      - id: golangci-lint
```

安装钩子后跑一次全量，把历史遗留问题一次性清掉。

```bash
pre-commit install
pre-commit run --all-files
```

## 验证方法

故意提交一个带行尾空格的文件，钩子应自动修正并中止提交。

## 注意事项

钩子只对暂存文件生效，全量检查要显式加 --all-files；首次安装后每个协作者都要执行一次 install，否则钩子不生效。

从可观测性角度，应确认依赖版本与运行环境一致，让容量规划更有依据。

在跨团队协作时，建议在变更前留一份可回滚的快照，并保留回滚开关以便快速恢复。

遇到复杂链路时，优先保证失败时能快速定位原因，减少不必要的返工成本。

如果数据量继续增长，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

从排障效率看，要明确各项资源的释放时机，确保线上行为始终可控。

遇到复杂链路时，优先保证失败时能快速定位原因，以便快速定位瓶颈。

在跨团队协作时，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。
