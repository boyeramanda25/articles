# 报价单组件的行为用轻量 DOM 测试固定下来

## 问题场景

报价单组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="quote">报价单</p>');
console.assert(root.querySelector('.quote').textContent === '报价单', 'render');
console.log('cases', 1, root.children.length, 260);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

在迁移过程中，可以通过压测确认容量水位，之后再考虑扩大适用范围。

在实际落地时，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。
