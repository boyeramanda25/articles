# 仓库动画改用合成层属性避免重排

<!-- content-workspace-job:5c4fa4ef-459d-4e62-98ec-086bfb1ffd57 -->

## 问题场景

仓库抽屉用 left 做滑入动画，低端机上明显卡顿，滚动时更严重。

## 实现步骤

把位移改为 translate3d，动画结束位置由 transform 决定。

```css
.drawer {
  position: fixed;
  inset: 0 auto 0 0;
  width: 320px;
  transform: translate3d(-100%, 0, 0);
  transition: transform .25s ease-out;
  will-change: transform;
}
```

用 will-change 提前提示浏览器提升图层，动画结束后及时撤销。

```javascript
const drawer = document.querySelector('.drawer');
function toggle(open) { drawer.classList.toggle('open', open); }
drawer.addEventListener('transitionend', () => {
  drawer.style.willChange = 'auto';
```

## 注意事项

will-change 不宜长期常驻，会占用显存；大量元素同时提升图层反而更慢。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

在实际落地时，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。

对于刚接手的同学，应定期回顾相关监控指标，以便后续复盘有据可查。

结合团队现状，可以通过日志补充上下文信息，保证每一步都可验证。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。

在迁移过程中，可以通过日志补充上下文信息，使整体改动风险可控。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。
