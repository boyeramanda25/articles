# 奖金模块按路由拆分后再懒加载

<!-- content-workspace-job:22813280-4656-49fe-98e6-03f1c1882f3c -->

## 问题场景

奖金后台首屏加载了全部页面代码，包体积接近三兆，弱网下白屏时间很长。

## 实现步骤

路由配置里用动态 import 替代静态引入，构建工具会自动拆包。

```javascript
const routes = [
  { path: '/', component: () => import('./Home.js') },
  { path: '/bonus', component: () => import('./BonusPage.js') },
];
```

给懒加载组件加加载态与错误兜底，避免等待期间没有任何反馈。

```javascript
async function navigate(path) {
  const hit = routes.find((r) => r.path === path) || routes[0];
  const mod = await hit.component();
  return mod.default ? mod.default() : mod.render();
}
```

## 注意事项

拆得太细会产生大量小请求，反而拖慢首屏；预加载策略要按真实路径设置，否则等于没拆。

结合团队现状，可以通过压测确认容量水位，便于横向对比不同方案的效果。

在迁移过程中，可以通过压测确认容量水位，避免资源被长期占用。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

对于刚接手的同学，要明确各项资源的释放时机，确保线上行为始终可控。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

在压测阶段，应把关键参数集中到配置中心统一管理，避免问题积累到难以收场。
