# 用唯一索引兜住评论表的重复写入

<!-- content-workspace-job:ac779177-78bf-4343-b229-116ae99a3f09 -->

## 问题场景

评论表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE comments ADD UNIQUE KEY uk_likes (likes);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO comments (id, likes) VALUES (1, 30)
ON DUPLICATE KEY UPDATE likes = VALUES(likes);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。

```sql
SELECT COUNT(*) FROM comments WHERE likes = 100;
```
