# 总账字典查询加上缓存后减少重复计算

<!-- content-workspace-job:759a0eb0-7efc-4b8e-a7a3-203e07e7b1c2 -->

## 问题场景

每次渲染总账详情都要重复计算同一组派生字段，调用量一上来 CPU 就被同一段逻辑吃掉。

## 实现步骤

把派生逻辑抽成只依赖入参的纯函数，加 lru_cache 并设定合理容量。

```python
from functools import lru_cache

@lru_cache(maxsize=1024)
def summary(ident, version):
    rows = fetch_rows(ident)
    return {"id": ident, "total": sum(r["debit"] for r in rows), "v": version}
```

数据变更时主动调用 cache_clear，或把版本号作为入参的一部分。

```python
def invalidate():
    summary.cache_clear()
    return summary.cache_info().currsize
```

监控缓存命中率，命中率长期偏低说明入参过于分散，缓存没有意义。

```python
a = summary("ledger-1", 880)

print(a == b, summary.cache_info().hits)
```

## 验证方法

连续调用同一参数两次，第二次的耗时应显著低于第一次，且返回值完全一致。

## 注意事项

lru_cache 要求入参可哈希，传列表会直接报错；缓存会延长对象生命周期，大对象要设 maxsize。

在资源受限的环境下，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。
